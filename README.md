# グラウンドアップ シフト表 自動生成

リハビリスタジオ グラウンドアップの毎月のシフト表作成を自動化するプロジェクトです。
横浜市 地域密着型通所介護の監査提出様式「従業者の勤務の体制及び勤務形態一覧表」に
沿った形式で、Excelファイル（午前シート・午後シートの2枚）を出力します。

## 現状（v2でできること・できないこと）

現在のシフト作成は、ご本人の「作成手順」によると次の4ステップです。

1. リセット作業（月を変更し、常勤は基本パターンを、パートは固定曜日を一旦出勤にする）
2. 休み希望をそのまま反映する
3. 常勤は所定勤務日数に合わせる
4. 足りない日の調整

**v2ではステップ1〜4をすべて自動化しています。**
ステップ3は「実質所定日数（有休を除く）」に対する不足分を、その時点で最も手薄な
営業日から自動的に埋める形で調整します。ステップ4は「Totalが4〜6人になるよう、
スタッフが『勤務可能』欄に記載した日を自動的に組み込む」形で対応しています
（記載がない日まで自動で人を追加することはしません＝安全側の設計）。
完成後は独立したレビュー処理がもう一度チェックし、結果をレポートに出力します。
それでも最終的な人の目でのチェックは必要です（詳細は下記）。

## 営業日と、常勤の所定勤務日数（2つの別ルール、ユーザー確定・2026-09時点）

**この2つは別の概念なので混同しないこと。**

### (A) 営業日（スタッフに勤務させて良い日）

```
営業日 = 日曜、および下記の固定休業期間を除くすべての日
  ・5/3, 5/4, 5/5（ゴールデンウィーク）
  ・8/13, 8/14, 8/15（お盆）
  ・12/30, 12/31（年末）
  ・1/1, 1/2, 1/3（年始）
```

毎年同じ月日で固定（`generate_shift.py` の `FIXED_CLOSURE_MD`）。この日は常勤・パート
問わず誰のシフトにも自動では何も入れません（Total人数は自動的に0になります）。

### (B) 常勤スタッフの所定勤務日数（休日クオータの計算）

事業所は日曜以外営業。常勤は「土日祝日の日数分」休みを取る（土曜や祝日に出勤した分は
別の平日で調整して帳尻を合わせる）。ここでの「祝日」は国民の祝日（jpholidayで判定）
すべてを指し、(A)の固定休業カレンダーとは別物です。事業所自体はその祝日も営業して
いる場合がありますが、常勤スタッフの休日クオータとしてはカウントします。

```
所定勤務日数 = その月の日数 - (土曜日数 + 日曜日数 + 祝日日数)
所定勤務時間 = 所定勤務日数 × 8時間
```

例: 2026年10月は31日中、土日祝日が10日（土5・日4・祝1）なので所定21日・168時間。

休み希望を反映すると所定日数を下回ることがありますが、これは**ステップ3として自動で
調整されます**：不足しているスタッフについて、その時点で配置人数が最も少ない営業日
（土曜も含む）から順に、6日以上の連続勤務にならない範囲で出勤日を追加していきます。
それでも候補日が足りず不足が残る場合のみ、`..._report.txt` に警告として出ます。

**有給休暇は「所定日数」とは別枠で休みとして扱います。** 休み希望に `paid_leave` が
ある場合、その日数分だけ実質的な所定勤務日数を差し引いて（例: 所定21日・有休1日なら
実質所定20日）、ステップ3の自動調整はその実質所定日数に合わせます。公休（土日祝日）の
調整とは別物として扱われるため、有休を取っても他の平日で「埋め合わせ」を強制されません
（＝有休を取った分、稼働日数は実質所定日数までしか埋まりません）。

**有給の日もシフト表には「有」というシフト記号を明記し、月合計・週平均勤務時間数
（AX/AZ列）にも通常勤務と同じ時間数として反映します**（ユーザー確定ルール、2026-10）。
これにより、常勤スタッフの月間勤務時間数は有休の有無にかかわらず所定どおりの時間数
（例: 2026年10月なら168時間/月、週平均は暦月モードの計算式どおり）で揃います。
「有」はshift_codes.csvにAM/PM用がそれぞれ4.0時間（サービス提供時間内3.0時間）で
定義済みで、実際にこれまでも実績シートで使われてきた記号です。なお、Total（配置人数、
row84）の集計上も「有」はサービス提供時間内の勤務時間数が0より大きいため、他の勤務日
と同様にカウントされます（実績シートでの既存の使われ方に合わせています）。稼働日数
（各スタッフの実質所定日数との一致チェックやレポートの日数表示）は、有休の日を除いた
実際の勤務日数で数える点は従来どおりです。

常勤スタッフ: 上口由佳、板倉芽生、山田恵美、高山岳、宮路愛
パートスタッフ: それ以外（永田、鷹野、若尾、大野、織田、藤田、金上）

※ 島倉一成さんは2026年10月時点で退職済みのため `staff_master.csv` から削除済みです。
  コピー元の月シート（9月1・9月2）には実際の9月の勤務実績が残っているため、
  監査保存の観点からそのデータ自体は消さず残してあります。出力側では
  `generate_shift.py` が自動的に氏名・職種・資格欄を空欄にするので、以降の月は
  手動対応不要です（詳細は下記「退職者の名前が様式に残り続ける場合」参照）。

## Total人数（配置人数）を4〜6人にする調整（ステップ4）

横浜市様式の「Total」（`(18) 1日の職種別人員内訳`の合計、row84）は、見た目より複雑な
集計ルールです。**この2条件を両方満たす行だけがカウントされます:**

1. 職種が「生活相談員・看護職員・介護職員・機能訓練指導員」のいずれかであること
   （**管理者・送迎職員はカウント対象外**。様式のL80:L83に列挙された職種のみが対象）
2. その日のシフト記号の「サービス提供時間内の勤務時間数」が0より大きいこと
   （例: 管理者の事務作業用記号 `b` は8:30〜9:00でサービス提供時間`9:00〜`に
   掛かっていないため、勤務していてもカウントされません）

`generate_shift.py` はこの2条件をPythonで再現して daily_counts を計算しており、
LibreOffice上での実際のCOUNTIFS/SUM再計算結果と完全一致することを確認済みです
（2026年10月で検証）。

**Total人数が4〜6人の範囲外（4人未満、または7人以上）の営業日は出力Excel上で
Totalセルを赤く強調表示**し、レポートにも警告を出します（ユーザー確定ルール、
2026-10）。自動的に埋めるのは「勤務可能」欄（下記）に記載がある場合のみで、記載が
ない場合は人を追加せず赤字で警告するだけにしています（安全側の設計。誰を追加で
出勤させるかは現場判断が必要なため）。6人を超える日も同様に赤字表示されますが、
自動では減らしません（パートの固定曜日契約や常勤の所定日数を勝手に削ることに
なるため。手動調整が必要です）。

## 「(12)週平均勤務時間数」欄（AZ列）の#NAME?エラーについて（2026-10修正）

ベース様式（`シフト2026.xlsx`）の9月1・9月2シートには、本来シート内で完結すべき
「(12)週平均勤務時間数」の数式（暦月モード）に、なぜかコピー元シート名（`'9月1'!`や
`'9月2'!`）がそのまま埋め込まれているセルが複数ありました（各シート32箇所）。
`copy_worksheet()`はセルの数式を文字列としてそのままコピーするため、毎月このシート名
を書き換えないと、コピー元シートが出力に含まれなくなった時点で`#NAME?`エラーになります
（出力を「その月の2タブのみ」にする変更を入れた際に顕在化・ユーザー報告で発覚）。

`generate_shift.py`は複製直後にこのシート参照部分を自動的に取り除き、自シート内の
自己参照に修正するようにしました。これにより毎月自動的に解消されます。

## 「(15)利用者数」「(16)サービス提供時間」を対象月の曜日に合わせて書き直す（2026-10対応）

ベース様式の(15)利用者数（定員15人）・(16)サービス提供時間（平均3時間）の行は、
日付列ごとの固定値で、複製元の月では日曜の列だけ空欄になっています。この値も
`copy_worksheet()`でそのままコピーされるだけなので、複製元の月と対象月とで日曜の
位置がずれると、対象月の日曜ではない列が空欄のまま、日曜の列に値が残ったままに
なってしまいます。

`generate_shift.py`は複製元シートに入っている「営業日の値」（定員数・平均提供時間、
通常は月をまたいで一定）を読み取り、対象月の日曜・固定休業日（非営業日）の列は
**0**、それ以外の営業日の列はその値、で毎回書き直すようにしました（ユーザー確定
ルール、2026-10）。月の日数を超える列（例: 30日までの月の31日目）は空欄のままです。

## 常勤スタッフの月間勤務時間数が80時間・84時間など人によって異なっていた件について（2026-10対応済み）

以前は、有休を取得した常勤スタッフだけ月間実績時間数が所定より少なく表示される
仕様でした（例: 板倉芽生さん・宮路愛さんは10月に有休1日＝実質所定20日×4時間＝
80時間、有休0日の高山岳さんは所定21日×4時間＝84時間、という具合に人によって
バラついていました）。

ユーザー確認の結果、**「有休も時間数に含めて計算する」（＝有休の日も所定どおりの
時間数としてカウントする）** という運用に統一することが確定しました（2026-10）。
これにより、有休の有無にかかわらず常勤スタッフの月間実績時間数は所定どおりに揃い
ます（例: 上記2名も含め168時間/月の所定に対して揃った値になります）。具体的には
有休の日もシフト表に「有」という記号を明記し、月合計・週平均勤務時間数（AX/AZ列）
にも通常勤務と同じ時間数として反映されるようにしました。詳細は上記「有給の日も
シフト表には『有』というシフト記号を明記し…」の節を参照してください。

（横浜市様式の注意書きには「有休のシフト記号は時間をすべて0:00にする」という
記載もあるとされていますが、今回のユーザー確認により、グラウンドアップでは時間を
入れる現状の運用を継続する方針で確定しています。`docs/format-notes.md`の
「未解決・要確認事項」もあわせて更新済みです。）

## ファイル構成

```
shift_codes.csv           シフト記号表（a〜z, 有など）の時間定義。Total集計の判定にも使用
staff_master.csv          スタッフ一覧（職種・勤務形態・資格・パートの固定曜日・既定のシフト記号）
generate_shift.py         シフト表生成スクリプト（v2: ステップ1〜4を自動化）
generate_request_sheet.py スタッフ用「シフト希望入力シート」（通年）を生成するスクリプト
parse_request_sheet.py    記入済みの希望入力シートを requests_YYYYMM.csv に変換するスクリプト
シフト2026.xlsx            横浜市様式 + 実績データが入ったベースファイル（8月・9月分）
output/                   生成したシフト表と、日別・スタッフ別サマリーレポートの出力先
docs/format-notes.md      横浜市様式の構造・数式・用語の調査メモ
```

## staff_master.csv で毎月確認・更新すること

- `fixed_weekdays_am` / `fixed_weekdays_pm` … パートさんの固定勤務曜日（例: `火,木,土`）。
  午前・午後で曜日が異なる人がいる（例: 大野さんは土曜AMのみ、若尾さんは土曜PMのみ）ため
  2列に分かれています。**両方空欄のスタッフ（藤田さんなど）は「不定期勤務」として
  自動生成の対象外になり、手作業での入力が必要です**（意図的な仕様）。
- `default_code_am` / `default_code_pm` … その人がいつも使うシフト記号。複数の記号を
  使い分けている人（永田さんのd/eなど）は要確認。
- 常勤（keitai A/B）は `fixed_weekdays_*` 不要。所定勤務日数は自動計算されます
  （上記「常勤スタッフの所定勤務日数」参照）。
- 新しいスタッフが入ったら行を追加、辞めたスタッフは行を削除してください。
- 同じ人が複数の職種を兼務している場合（上口さん＝管理者+生活相談員など）は、
  役割ごとに行を分けて登録してください。スクリプトは氏名と職種（シートのC列）の
  組み合わせでマッチングし、氏名単位でグループ化して**同じ日に揃えて出勤日を
  割り当てます**（No1の管理者行とNo2の生活相談員行が別々の日になることはありません）。
  なお `role` 列は様式シートのC列の表記と完全一致させる必要があります（山田さんは
  様式シート上「生活相談員」の行もありますが実際の勤務記録は「介護職員」の行に
  入るため、`role` は `介護職員` にしてあります。2026-09に実績シートで確認済み）。

## 使い方

```bash
pip install openpyxl jpholiday

python3 generate_shift.py \
  --base シフト2026.xlsx \
  --source-am "9月1" --source-pm "9月2" \
  --year 2026 --month 12 \
  --staff staff_master.csv \
  --requests requests_202612.csv \
  --out output/シフト2026_12月_案.xlsx
```

`--requests` は休み希望・勤務可能希望のCSV（省略可）。形式:

```
name,date,status
上口由佳,2026-12-21,off
織田陽子,2026-12-24,paid_leave
永田千尋,2026-12-05,am_only
大野リカ子,2026-12-10,available
```

- `off` … その日は休み
- `paid_leave` … 有休（公休＝土日祝日とは別枠の休みとして扱う。給与処理は別途）。
  シフト表には「有」というシフト記号として明記され、月合計・週平均勤務時間数にも
  通常勤務と同じ時間数として反映されます（2026-10確定ルール）。
- `am_only` … 午前のみ出勤可（午後シートからは外す）
- `pm_only` … 午後のみ出勤可（午前シートからは外す）
- `available` … **勤務可能（休み希望とは別の欄）**。記載がある日は営業日である限り、
  その人のシフトに自動的に組み込まれます（午前・午後どちらのシートにも適用）。
  Total人数が手薄になりそうな日がわかっている場合、対象スタッフにこの欄で
  「その日は出られます」と申告してもらうと、自動調整で埋まりやすくなります。

実行すると `output/` に

- `シフト2026_12月_案.xlsx` … その月のシフト案。ユーザー確定ルール（2026-10）により
  **「12月1」「12月2」の2タブだけ**を出力します（`--base` に含まれる記入方法・
  記載例・過去月のシートなどは複製元として読み込むだけで、出力には含めません）。
  ただし「シフト記号表（勤務時間帯）」と「プルダウン・リスト」の2タブだけは、
  12月1・12月2シート内の勤務時間数・Totalの数式や、職種・資格のプルダウンが
  参照しているため削除せず残しています（削除するとTotalが0になったり、
  Excelで開いたときに警告が出たりします）。横浜市への提出時は、この
  シフト記号表タブも一覧表とセットで提出してください。
  Excelで開くと自動的に勤務時間数・職種別人員内訳・Totalが計算されます。
  Total人数が4〜6人の範囲外（4人未満・7人以上）の営業日は赤く強調表示されます。
- `シフト2026_12月_案_report.txt` … スタッフ別の稼働日数、日別のTotal・職種別内訳、
  完成後の自動レビュー結果（所定日数・Total4〜6人・連続勤務6日未満・兼務者の
  勤務日一致・staff_master.csvとの対応漏れ、の5項目をチェック）

が出力されます。**レビュー結果に✗が1つでもあれば、案をExcelで開いて内容を確認・
修正してから**、監査保存用として保管してください。

### 退職者の名前が様式に残り続ける場合

`--source-am` / `--source-pm` に指定したシート（例: 9月1・9月2）に、
`staff_master.csv` に存在しない氏名（退職者など）の行があった場合、
`generate_shift.py` は**出力シート側だけ**その行の氏名・職種・勤務形態記号・資格欄を
自動で空にします（他の行で正しくマッチしている現職スタッフの未使用重複スロットは
対象外）。コピー元シート（9月1・9月2など）自体の実績データは、監査保存の対象なので
一切変更しません。そのため手動対応は不要で、レビュー結果も「問題なし」になります。

※ 過去（2026-09時点）は「複製元シートで手動で氏名欄を消してください」という運用
  でしたが、9月シートには実際の9月の勤務実績が入っており、それを消すと監査保存の
  データが失われてしまうことが判明したため、2026-10に上記の自動処理へ変更しました。
  複製元シートのデータは今後も一切書き換えません。

## スタッフ用「シフト希望入力シート」（休み希望・出勤可能・有給の収集）

`--requests` に渡すCSVを毎回手作業で作るのではなく、スタッフ本人がExcelに直接
入力できる通年シートを用意している。使い方は次の2ステップ。

### 1. 入力シートを配布する（年1回でOK）

```bash
python3 generate_request_sheet.py --year 2026 --staff staff_master.csv \
  --out "output/2026年_シフト希望入力.xlsx"
```

- ブック内に「記入方法」シート＋「1月」〜「12月」の月別シートが作られる
- 月別シートは **行=日付、列=スタッフ名** の表で、各スタッフは自分の列の
  該当する日のセルをクリックし、プルダウンから「休み希望」「出勤可能」「有給」の
  いずれかを選ぶだけ（自由入力ではないのでタイプミスによる集計漏れが起きにくい）
- 日曜日・固定休業日（(A)営業日のルールと同じ）は自動でグレー表示になり、
  入力不要であることが一目でわかる
- このファイルをスタッフ全員に配布し、各自が自分の列に入力してもらう
  （Googleドライブ等で共有し、同じファイルに各自入力してもらう運用を想定）

### 2. 記入済みシートを月次CSVに変換する（毎月）

```bash
python3 parse_request_sheet.py \
  --sheet "output/2026年_シフト希望入力（記入済み）.xlsx" \
  --staff staff_master.csv --year 2026 \
  --outdir output/requests_2026
```

- 月ごとに `requests_202601.csv` 〜 `requests_202612.csv`
  （希望が1件もない月はファイルを作らない）が `output/requests_2026/` に出力される
- 「休み希望」→ `off`、「出勤可能」→ `available`、「有給」→ `paid_leave` に自動変換
  される（`am_only` / `pm_only` はこのシートでは扱っていない。必要な場合は出力された
  CSVに手作業で行を追加・修正する）
- staff_master.csvに存在しない名前や、プルダウン以外の値が入っていたセルは
  無視され、実行後にまとめて警告表示される
- 出力されたCSVをそのまま `generate_shift.py --requests` に渡せる

## 監査保存について

横浜市の地域密着型通所介護では、勤務形態一覧表の保存義務があります。生成したExcelは
`output/` に残るので、月ごとにファイル名を変えて（例: `シフト2026_12月.xlsx`）GitHubに
コミットしておけば、変更履歴つきで保管できます。
