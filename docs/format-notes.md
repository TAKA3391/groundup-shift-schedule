# 横浜市様式「従業者の勤務の体制及び勤務形態一覧表」調査メモ

出典: 横浜市 [勤務形態一覧表様式・料金表作成例【地域密着型サービス】](https://www.city.yokohama.lg.jp/business/bunyabetsu/fukushi-kaigo/kaigo/shinsei/service/kinmu.html)
（地域密着型通所介護用: `78_kinmuhyo_202607.xlsx`）

## シートの構成（グラウンドアップの実運用ファイル シフト2026.xlsx）

- `9月1` / `9月2`, `8月1` / `8月2` … 実際に作成・提出した月次シフト表。
  **`◯月1` = 午前（1単位目）、`◯月2` = 午後（2単位目）**。
  この施設は「サービス提供単位数＝2」（午前クラスと午後クラスを別々に運営）のため、
  横浜市への提出上、午前・午後で別々の勤務形態一覧表を作成する必要がある。
- `シフト記号表（勤務時間帯）` … a〜z等のシフト記号と、始業・終業・休憩・勤務時間数、
  サービス提供時間内の勤務時間数の対応表。**要提出**（メインの一覧表とセットで出す）。
- `記入方法` … 横浜市が配布する記入マニュアル（提出不要、参照用）。
- `【記載例】...` … 記入例（提出不要）。

## 勤務形態一覧表シートのセル構造

- `AC2` = 年（西暦）, `AG2` = 月
- `BB6` = 常勤が勤務すべき時間数（週）, `BB8` = 当月の日数（`=DAY(EOMONTH(DATE(AC2,AG2,1),0))` という数式で年月から自動計算）
- `BB10`〜`BB15` = サービス提供単位数・何単位目か・サービス提供時間
- 日付ヘッダー: 22行目=日付（1〜31）, 23行目=月内の曜日カウンタ, 24行目=曜日（月火水木金土日）
  列は **S列(19列目)を1日目** として1日1列、最大 AW列（31日目）まで。
- スタッフ1人につき3行1組（例: 25〜27行目）
  - 1行目: `B`=No, `C`=職種, `G`=勤務形態記号(A/B/C/D), `H`=資格, `L`=氏名,
    日付列に**シフト記号**（a, b, c…）を直接入力
  - 2行目: `P`列ラベル「勤務時間数」。日付列は数式
    `=IF(S25="","",VLOOKUP(S25,'シフト記号表（勤務時間帯）'!$C$6:$K$35,9,FALSE))`
    でシフト記号表から自動計算。`AX`列=月合計、`AZ`列=週平均。
  - 3行目: `P`列ラベル「サービス提供時間内の勤務時間数」。同様にVLOOKUPで自動計算（列19番目）。
- **つまり実際に人手で入力するのは「シフト記号」1行だけ**で、時間数・合計・週平均はすべて
  シートの数式が自動計算する。自動化の本丸は「どの日にどのスタッフに何のシフト記号を
  割り当てるか」を決めること。

## 勤務形態（G列）の記号（`記入方法`シートより）

| 記号 | 区分 |
|---|---|
| A | 常勤で専従 |
| B | 常勤で兼務 |
| C | 非常勤で専従 |
| D | 非常勤で兼務 |

常勤/非常勤の判定は「その事業所の常勤が勤務すべき時間数（BB6, 週40時間など）に達しているか」
であり、雇用形態（正社員/パート）そのものではない。専従/兼務は「1つの職種のみに従事＝専従、
複数の職種を兼務＝兼務」。

## シフト記号表の中身（`shift_codes.csv` に抽出済み）

- a〜i: 始業・終業・休憩から勤務時間数を計算する通常のシフト（例: a = 8:30〜12:30 休憩なし = 4.0時間）
- j, k, n〜s: 未使用（記号だけ予約されている）
- 有 / 有休: 有休用の記号。始業・終業等は通常のシフトと同じ時間を入れるが、
  横浜市の指示では「有休のシフト記号を作る場合は始業・終業・休憩・開始・終了はすべて0:00にする」
  という注意書きもある（現状の運用では時間を入れているため、要確認・要相談）。
- u〜z: 時刻ではなく時間数を直接入力するための記号（「○：○○〜○：○○」の形で書けない場合用）

## グラウンドアップの「シフト作成の手順」（ユーザー作成、`作成手順`シートより）

1. リセット作業
   - 月を変更する
   - 常勤スタッフの日曜以外を一旦出勤にする（1人作成したらコピペ）
   - パートスタッフの固定曜日を一旦出勤にする（ひな形からコピペで作成）
2. 休み希望をそのまま反映する（常勤・パートとも）
3. 常勤は所定勤務日数に合わせる
4. 足りない日の調整

## v1.2スクリプトでの実装方針

- ステップ1・2を自動化（`generate_shift.py`）。既存の月シート（例: `9月1`）を
  `openpyxl.copy_worksheet()` で複製し、日付ヘッダーを対象月に書き換えたうえで、
  スタッフごとにシフト記号だけを書き込む。数式・書式は複製元からそのまま引き継がれる
  ので、Excelで開けば時間数・合計は自動計算される。
- ステップ3も自動化した（`process_unit()` の二段階処理）。
  - Pass 1: 既定パターン（ステップ1）に休み希望・有休（ステップ2）を反映して
    仮のシフトを組み、日別の職種別配置人数（`daily_counts`）を集計する。
  - Pass 2: 常勤スタッフ（keitai A/B）ごとに、実質所定日数
    （`full_time_target_days()` − 有休日数）に対する勤務日数の不足分を計算し、
    不足がある場合は「まだ出勤していない・休み希望でブロックされていない土曜日」を
    候補として、Pass 1で集計した配置人数が少ない日から順に（`sorted by
    (daily_counts[day], day)`）出勤を追加していく。追加するたびに
    `daily_counts` を更新するので、複数の常勤スタッフを埋める際も偏りにくい。
    候補日が尽きても埋まらない場合は `shortages` に記録し、レポートに警告として出す。
  - 有給休暇（`paid_leave`）は公休（土日祝日）とは別枠で扱う。有休の日数分だけ
    「実質所定日数」を所定日数から差し引き、Pass 2の不足判定・自動補充はこの実質
    所定日数を基準にする（＝有休を取っても、他の平日への埋め合わせを強制しない）。
- ステップ4（最低人員基準を満たすための最終判断）は引き続き人手判断が必要なため、
  「スタッフ別稼働日数」「日別・職種別配置人数」のレポートを出力するだけに留めている。
